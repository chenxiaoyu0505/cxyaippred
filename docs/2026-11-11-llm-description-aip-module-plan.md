# 抗炎肽 AIP 预测：LLM 序列描述模块研究计划（合并版）

- 日期：2026-11-11
- 状态：**方案，尚未实现，也没有任何实验结果**。先评审，再按证据门槛实施。
- 来源：合并桌面版《抗炎肽LLM-PLM融合模型新计划》与 `docs/2026-11-11-llm-description-aip-module-plan.md`（初稿）。两版冲突处，以当前仓库代码与数据为准。

## 0. 项目背景

仓库：[cxyaippred](https://github.com/chenxiaoyu0505/cxyaippred)。

当前模型：冻结的 ESM-2 650M 残基表示 → ResCNN + 掩码均值池化 → 拼接 704 维手工特征（694 维基础块 + 10 维两亲性）→ MLP 输出 AIP 概率。

当前默认协议（`data/splits/split_origtest_cv5_seed42_nobip/`）：4,182 条训练池 + 452 条固定 test；5 折的 train/val 只在训练池内切，452 条 test 每折相同。规范主表为 4,634 行（BIP-free）。

历史随机五折基线 AUROC 0.7277 / AUPR 0.6494，仅作项目背景，**不作为本方案的对照数字**；EMA-SAT 等训练技巧未显示稳定排序增益，本计划不再以堆叠训练技巧为主线。

已具备：固定划分、特征缓存、按训练折拟合的标准化、训练/评估分离、配置/概率/代码哈希留痕、val AUROC 早停（AUPR 并列记录）。

## 1. 研究问题与贡献边界

给一条仅有氨基酸序列的肽，冻结的通用生成式 LLM 能否在**不读取该肽的 AIP 标签、注释或数据集身份**的条件下，生成有区分力的生物物理描述？描述向量能否在 ESM-2 表征与 704 维手工特征之外，对 AIP 预测提供稳定增量？这种增量能否在低相似度或真正外部的样本上保持？

这里的“零样本”仅指**描述生成器未用本 AIP 标签训练**。文本向量分类器与融合头仍须用 AIP 标签监督训练，不能把整个系统称为零样本分类器。生成文本是序列的派生表示，不是独立实验测量，也不是已验证的作用机制。

三层检验分开报告：

1. **LLM 直接判断**：单独提示 Qwen 给 AIP 判断，不训练分类头；只作零样本参考，不进入融合特征。
2. **描述本身可用性**：提示词禁止输出 AIP 类别或概率；描述经冻结文本编码器变向量，用简单监督分类器预测标签（text-only）。优于随机不等于有互补性。
3. **对现有模型的增量**：在 ESM-2 + 704 维手工特征上加入文本向量，与完全相同的数据划分、训练预算和参数量对照。这是决定模块是否进入主模型的核心检验。

## 2. 相近工作与候选贡献

- [ProtST（ICML 2023）](https://proceedings.mlr.press/v202/xu23t.html)：用已有蛋白属性文本与序列做多模态预训练；不是为每条输入肽即时生成自由文本再用于 AIP 分类。
- [BetaDescribe（PNAS 2026）](https://pubmed.ncbi.nlm.nih.gov/42372160/)：从序列生成蛋白描述，包括低相似度蛋白；“未知序列生成描述”本身不能声称首次提出。
- [HD-AIP（Bioinformatics 2026）](https://pubmed.ncbi.nlm.nih.gov/42765504/) 与 [AIPFusion-Net（Front. Mol. Biosci. 2026）](https://pubmed.ncbi.nlm.nih.gov/42898259/)：已在 AIP 预测中融合 PLM、局部序列或手工特征；后者也做交互融合。单纯拼接、乘积、差值不是足够的架构创新。
- Prot2Text / Prot2Text-V2：把蛋白表示解码为自然语言，方向与本方案相反。

**候选贡献**：在严格标签盲、数据来源盲的条件下，系统检验通用 LLM 的序列描述是否构成可迁移的 AIP 先验；定量拆开“生成器知识”“文本编码器直接读序列”“手工理化信息改写”“模型容量”四种来源。若证据支持，再讨论轻量融合；不宣称生成的机制描述已获生物学验证。查新仍不完整，投稿前须系统检索。

## 3. 数据协议与泄漏边界

- 提示词开发、文本格式选择、模型与超参选择只依据训练池内的 train/val；**冻结生成器、提示词、解析和融合配置后**才评估 test，不依据 test 结果回改。
- 生成器每次只接收一条序列；不传标签、文件名、数据来源、划分或其他肽；不联网、不接 RAG/注释库。缓存按规范化序列哈希索引，另存模型 revision、量化文件哈希、提示词哈希、解码参数、文本编码器 revision 和代码哈希。
- 离线与标签盲不能证明 Qwen 预训练没见过公开肽。报告已知精确/近似重叠；把“训练集未见”与“预训练未见”分开表述。
- 452 条 test 的 5 个模型分数不是 5 份独立测试样本。比较模型时保存每条 test 肽的配对概率；报告集成时先按预定规则合成每条肽一个概率，再按**肽为抽样单位**算配对差值与置信区间。
- 旧 `experiments/cv5` 是不同数据、旧架构的历史结果，不能作数值对照。
- 外部候选 `data/HD-AIP_independent_303.csv` 已删除，不再使用：它与 `aip_all` 精确重叠 59 条（57 条在 452 test、2 条在训练），去重后仅 244 条（104 正），且有 2 条标签冲突。重要泛化主张需要另找真正外部或时间外测试集。
- 相似性泄漏：train/test 精确重叠为 0，但实测 23 对近似重复（22 条 test 与训练序列同长度、差异 ≤10%），报告时宜同时给出“去掉这 22 条”的分数。
- 统计功效：452 test / 175 阳，AUROC/AUPR 的 95% CI 都在 ±0.05 量级；+0.02 量级的增量测不出。主指标（AUROC，AUPR 并列）与最小可检测效应须预注册；5 seed 只解决训练方差，不解决测试集太小。

## 4. 生成与编码方案

硬件已确认：本次离线生成在 **Apple M4 Mac mini、24GB 统一内存**上进行。推荐先用 [Qwen3-8B 8bit MLX](https://huggingface.co/mlx-community/Qwen3-8B-8bit) 逐条生成、[Qwen3-Embedding-0.6B](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B) 编码，两者均冻结；两步分进程运行，描述只生成一次并缓存。生成模型文件约 8.72GB；若实测内存或吞吐不合适，再试 [Qwen3-8B 4bit MLX](https://huggingface.co/mlx-community/Qwen3-8B-4bit)（约 4.62GB），作为独立量化条件记录。可选 [Llama-3.1-8B-Instruct 4bit MLX](https://huggingface.co/mlx-community/Llama-3.1-8B-Instruct-4bit) 做跨模型家族复核。

**提示词（研究先验版；描述与推断分层）**：

```text
请只以给定氨基酸序列作为该肽的样本信息，结合你已有的一般生物物理和肽研究知识，提出可检验的特征与假设。无需联网或检索；不要声称你查阅了具体论文。

要求：
1. 将直接可见的序列模式、较有依据的保守推断、探索性功能/机制假设分开；
2. 每条推断写出序列依据；探索性假设还要写一般研究依据与可检验预测；
3. 不输出该肽的活性类别、概率或已验证结论；没有依据时写 unknown；
4. 不虚构论文、具体靶点、细胞因子或定量活性；
5. 固定输出 JSON：
{
  "sequence_observations": ["..."],
  "conservative_inferences": [{"feature": "...", "sequence_basis": "..."}],
  "exploratory_hypotheses": [{"feature": "...", "sequence_basis": "...", "general_rationale": "...", "testable_prediction": "..."}],
  "uncertainties": ["..."]
}

序列：{sequence}
```

允许模型调用预训练得到的一般研究知识，正是本方案要检验的先验；不能把它的回忆或推测当成已核实的最新文献。主提示词保持中性；另预先登记一版“从抗炎相关视角提出候选假设”的任务定向提示词，作为独立实验条件。任务定向文本可能间接包含 AIP 判断，须与 Qwen 直接零样本判断和中性版分别比较，不能混称独立模态。

精确电荷、pI、分子量等仍由程序计算，不依赖 LLM 算术。预先固定采样配置、种子和最大输出长度，缓存原始输出；Qwen3 官方模型卡不建议对复杂生成用贪心解码，需在探针阶段检查格式及重跑稳定性。保守推断与探索性假设分别编码并消融，检验后者是否提供增量、是否增加错误。

环境：项目固定 `transformers==4.48.1`，Qwen3 官方要求 `>=4.51.0`，生成与文本编码放**独立环境**，只把版本化产物交给训练环境。Qwen3-Embedding-0.6B 默认最多 1024 维；按官方用法核对池化、归一化与任务指令。

## 5. 第一阶段：可行性探针

先从训练池分层抽约 200 条（覆盖正负、长度、理化范围），**不利用标签调文本**，人工审查：JSON 有效率、空/重复/模板化比例、不同序列的描述差异、明显虚构靶点/机制比例、单条时间与显存。

对等组成的随机重排序列重新生成描述，只测描述是否响应顺序变化；扰动序列没有可靠 AIP 标签，不能把该诊断当分类性能。

**停止条件**：JSON/描述质量不稳定、跨序列高度模板化、成本无法覆盖全数据，或文本变化主要是重复已有理化事实 → 先缩提示词和问题范围，不进入融合。

## 6. 预注册的最小对照

同一训练池内 5 折、相同模型种子、训练预算、早停与评估代码。先固定一个文本生成配置，不同时搜索提示词、融合架构、EMA 和 ESM 层号。主指标 AUROC；AUPR、MCC@0.5、MCC@val、Brier/ECE 和成本并列报告；保存每折、每 seed 的样本级验证预测。

| 代号 | 输入/方法 | 回答的问题 |
|---|---|---|
| B0 | 当前 ESM-2 + 704 维特征 | 真实主基线，须用当前协议重跑 |
| P | 仅 ESM-2；仅 704 特征 | 两支路各自贡献 |
| T | 冻结 Qwen 描述向量 + 简单分类器 | 描述是否含监督可利用信号 |
| S | 原始序列直接输入同一文本编码器 | 收益是否只是编码器从序列提特征 |
| H | 704 维特征生成固定文字模板，经同一文本编码器 | LLM 自由描述是否超过理化信息的文字重述 |
| F1 | B0 + 描述向量直接拼接 | 文本对完整基线是否有增量 |
| F2 | B0 + 描述向量，同维投影后加乘积/绝对差 | 简单交互是否超过 F1；须匹配头部参数量 |
| C | 空文本/打乱序列—文本配对，参数量匹配 F1 | 排除常量文本与容量造成的表观收益 |

Qwen 直接 AIP 判断单列零样本参考，不混入 T/F1/F2。打乱配对只是必要负对照，不能单独证明“机制知识”存在。F2 只在 F1 有稳定收益时启动；门控与 cross-attention 暂缓。

**进入主模型的判据**：F1 相对 B0 在多折/多 seed 的配对 AUROC、AUPR 上有稳定且有实际价值的增量，优于 S/H/C，且校准与成本可接受；固定 test 与外部集方向一致。若只有 T 高于随机而 F1 不增益，结论是“描述含标签相关信号”，**不是**它补充了 PLM。

## 7. 代码接入点与实施顺序

现状核对：

- `src/model_aip.py::AIPHead` 已有 `use_esm` / `use_hand` 开关，但无通用文本向量入口；
- `scripts/train_aip.py` 只有 `--lnn-only` 能同时关两支路，没有 `--no-hand` / `--no-esm`；
- `src/data_io.py::hand_feats()` 只能从序列重算，没有外部特征矩阵入口——原稿“动态 hand_dim 可接入新特征矩阵”属过度承诺，需先补入口（约 200–400 行）；
- `src/data_io.py` 按主表行号对齐，`scripts/train_aip.py` 每折只在 train 行拟合标准化；新文本支路必须复用同一套行号与拟合规则；
- `src/checkpoint.py` 格式为 v3，`scripts/predict.py` 按元数据复现输入。

实施顺序：

1. 独立脚本产出描述（`sequence_sha1,sequence,description,status,...`）与向量矩阵；严格校验行数、序列指纹、维度、有限值、模型/提示词版本，不得只凭形状复用缓存。
2. 实现 T、S、H 轻量探针与当前协议 B0；预处理参数只由每折 train 拟合。
3. 通过门槛后，给模型配置加显式 `text_mode/text_dim`，实现 F1；保留原 `AIPHead` 行为以便旧权重加载。新 checkpoint 写格式版本、文本配置与哈希；预测脚本必须能重生成同版描述，或要求用户提供可验证缓存。
4. 验证 train/val/test 行号对齐、单条与分批推理一致、保存/加载概率一致、文本缺失策略、旧 checkpoint 兼容；再考虑 F2。
5. 锁定 1–2 个候选配置做多 seed 配对验证；最后一次性评估固定 test，并计划外部验证。实验目录用新 ID，不覆盖 `cv5` 或其他历史产物。

## 8. 风险与暂缓

- 描述可能高度模板化，不同序列输出近似文本；
- LLM 可能生成合理但错误或不可验证的机制假设；
- 文本信号可能过弱，超不过 B0；
- 文本信号也可能只是零样本 AIP 判断的替代形式；
- 反复调提示词会自适应过拟合验证集；
- 生成与嵌入成本增加，增量尚不明确；Mac mini 上的单条耗时和运行峰值尚未实测，必须先做约 200 条试点；
- 生成/编码环境与现有 ESM 训练环境的依赖版本不同，须隔离并记录产物版本。

第一阶段暂缓：把融合向量解码回自然语言、soft-token 投影进 LLM、Qwen 联合训练、LLM 自动搜参、同时引入更多 PLM。

## 9. 给评审的问题

1. 上述最接近工作是否漏了“通用 LLM 对单条未知肽生成描述 → 嵌入 → AIP 分类”的先例？请给可核对的论文与方法差异。
2. T/S/H/F1/C 是否足以分离生成器先验、文本编码器、理化重述和容量效应？有无更省算力的等价对照？
3. 452 条 test 曾参与项目历史决策，是否还能称“独立测试”？哪份真正外部数据适合最终泛化检验？
4. Apple M4 Mac mini 24GB 统一内存上，Qwen3-8B 8bit MLX + Embedding-0.6B 的实现、版本隔离、运行峰值与失败备选是什么？
5. 描述质量的盲审量表、近同源控制和预注册的继续/停止门槛应如何设定？
6. 该方案是合理的方法学创新，还是仅模态堆叠？交互融合是否有更简单、更有辨识度的实现？

评审先回答这些问题并修订方案，再实施；不得引用任何尚未产生的性能数字。
